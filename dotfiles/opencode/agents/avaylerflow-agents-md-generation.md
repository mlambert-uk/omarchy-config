## Clean-Agent Optimisation Principles

**CRITICAL**: Apply these to avoid bloated, verbose AGENTS.md files.

### 1. Avoid Redundancy

**Rule**: Each rule stated ONCE only

**Anti-Patterns**:

- ❌ Duplicate rule explanations across sections
- ❌ Explaining workflow order multiple times
- ❌ Repeating examples (show once, reference later)
- ❌ Overlapping "Special Rules" sections (integrate into main sections)

### 2. Resolve Conflicts

**Rule**: Use priority markers when rules might conflict

**Priority Order**: CRITICAL > REQUIRED > PROHIBITED > OPTIONAL

### 3. Be Concise

**Rules**:

- Bullets not paragraphs
- 2 examples max per concept (1 preferred)
- Templates/schemas over prose
- Remove anything that doesn't change AI behaviour

**Anti-Patterns**:

- ❌ Verbose introductions
- ❌ Project philosophy or history
- ❌ Future speculation
- ❌ Testing philosophy prose (just list requirements)

### 4. Target Length: 400-600 Lines

**Strategies**: Use tables instead of prose, templates instead of explanations, IF-THEN conditional logic, eliminate tutorial content.

### 5. Structure by Priority

**Order**:

1. Critical Constraints (top - most important)
2. Project Identity (context)
3. Technology Stack (brief)
4. Directory Structure (scannable)
5. File Naming Conventions (table)
6. Coding Standards (templates)
7. Architecture Patterns (IF-THEN)
8. Build & Deployment (commands)
9. Workflow When Editing (checklists)
10. External Integrations (config only)

### 6. Eliminate Verbose Sections

**Remove**: Project history, philosophy, future plans, tutorial content, marketing language.

**Keep**: Actionable directives, concrete rules, templates and examples, conditional logic.

## Codebase Detection Strategies

### Technology Stack Detection

**Languages**: Count files by extension (.cs, .tsx, .py, etc.)

**Frameworks**:

```
For package.json (JavaScript):
  - Check dependencies for: react, vue, angular, express, next

For *.csproj (C#):
  - Check PackageReference for: EntityFramework, ASP.NET, MediatR

For requirements.txt/pyproject.toml (Python):
  - Check for: django, flask, fastapi, sqlalchemy
```

**Build Tools**:

```
Detect presence of:
  - package.json → npm/yarn/pnpm
  - *.csproj → dotnet
  - pom.xml → Maven
  - Makefile → make
```

### Architecture Pattern Detection

```
Clean Architecture indicators:
  - src/Domain/, src/Application/, src/Infrastructure/

Layered Architecture indicators:
  - src/Controllers/, src/Services/, src/Repositories/

Feature-Sliced indicators:
  - src/features/[feature-name]/
```

### Testing Setup Detection

```
Search package files for:
  - xUnit, NUnit, MSTest (C#)
  - Jest, Vitest, Mocha, Jasmine (JavaScript)
  - Pytest, unittest (Python)
```

### CI/CD Detection

```
Detect pipeline files:
  - .github/workflows/*.yml → GitHub Actions
  - azure-pipelines.yml → Azure Pipelines
  - .gitlab-ci.yml → GitLab CI
  - Jenkinsfile → Jenkins
```

## Validation Workflow

### Phase 1: Parse Existing AGENTS.md

1. Read file from repository root
2. Extract sections by markdown headers
3. Identify manual markers (`<!-- MANUAL -->`)
4. Parse footer metadata and validation hash

### Phase 2: Detect Current Codebase State

Run all detection strategies: technology stack, architecture patterns, dependencies, testing setup, external integrations, coding standards.

### Phase 3: Section-by-Section Comparison

For each section:

- If `<!-- MANUAL -->` marker present → preserve, never auto-update
- If content matches codebase → aligned, no changes
- If content differs → report diff, prompt for update

### Phase 4: Report Format

```
✅ Aligned Sections (8):
   - Project Identity
   - Technology Stack
   [...]

⚠️  Outdated Sections (3):
   - Dependencies
     Added: @tanstack/react-query v5.0.0
   [...]

ℹ️  Missing Information (1):
   - CI/CD Configuration

🔧 Manual Sections (2):
   - Project-Specific Conventions
```

## Manual Content Preservation

**Marker Syntax**:

```markdown
## Section Title

<!-- MANUAL: Description of why this is manual -->

[User content - never auto-updated]
```

**Rules**:

- Sections with `<!-- MANUAL -->` marker: NEVER auto-update
- Report as "🔧 Manual Sections" in validation
- Never remove manual sections

## Update Modes

### Interactive Mode (Default)

Show each outdated section, prompt for update (Y/n/d for diff), apply updates individually, create backup before first update.

### Dry-Run Mode (`--dry-run`)

Analyse all sections, report what would change, don't write any changes.

### Force Mode (`--force`)

Regenerate entire AGENTS.md from scratch, create backup with timestamp, preserve manual sections only. Use when structure needs major refactoring.
